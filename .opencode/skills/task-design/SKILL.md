## 🎯 Назначение (Purpose)
Skill преобразует проверенный Requirement Review в структурированный **Jira Tasks Artifact**, пригодный для последующего создания задач через Jira Tool.

> ⚠️ **Важно:** Skill проектирует содержание задач. Он не выполняет запись в Jira и не управляет Jira Tool напрямую.

## 📥 Входные данные (Inputs)

### Обязательные:
- Валидный Requirement Review Artifact
- Scope текущей задачи агента

### Опциональные:
- Проектные правила декомпозиции задач
- Допустимые типы задач, если они заданы Context
- Приоритеты или ограничения, явно переданные агентом
- Релевантная информация о существующих задачах, если агент уже получил её через Jira Tool

## 🧠 Управление контекстом (Context Management)
- Использовать Requirement Review как основной **Source of Truth** для проектирования задач
- Не возвращаться к полной истории чата, если необходимая информация уже содержится в валидном Requirement Review
- Не использовать существующие Jira-задачи как замену исходным требованиям
- Если агент передал данные о существующих задачах, использовать их **только** для предотвращения дублирования и согласования декомпозиции
- **Не запрашивать Jira самостоятельно**: Tool-вызовы выполняются агентом согласно Agent Instruction

## 📋 Процедура (Procedure)
Выполняй шаги последовательно:

1. Определи, какие подтверждённые требования требуют отдельной работы команды разработки
2. Сгруппируй связанные требования в логически целостные задачи
3. Разделяй задачи, если они имеют разные цели, разные критерии приёмки, независимые риски или могут реализовываться отдельно
4. Не дроби работу на задачи без самостоятельной ценности или проверяемого результата
5. Для каждой задачи сформируй понятный **Summary**
6. Сформируй **Description** на основании Requirement Review
7. Добавь **Acceptance Criteria** только из подтверждённых требований или явно переданного проектного Context
8. Сохрани **Traceability** к исходным требованиям
9. Укажи **Dependencies** между задачами, если они следуют из Requirement Review
10. Назначь **Priority** только если она может быть обоснована риском, бизнес-критичностью или явным Context, иначе оставь её неопределённой для агента или человека
11. Выяви потенциальные дубли относительно информации о существующих Jira-задачах, если такая информация передана
12. Сформируй **Jira Tasks Artifact**

## 🚫 Правила (Rules)
- ❌ Не создавать задачу, если для неё нет основания в Requirement Review
- ❌ Не добавлять Acceptance Criteria, которых нет в подтверждённых требованиях
- ❌ Не разрешать бизнес-неоднозначности самостоятельно
- ❌ Не смешивать в одной задаче независимые изменения без обоснованной причины
- ❌ Не создавать несколько задач, описывающих одно и то же изменение
- ❌ Не определять Jira Project, Assignee, Sprint, Fix Version или другие проектные поля самостоятельно, если они не переданы Context
- ❌ Не вызывать Jira Tool
- ❌ Не изменять существующие Jira-задачи

## 🧩 Паттерны рассуждений (Reasoning Patterns)

### 🌳 Branching / Tree
Может применяться, если существуют несколько существенно разных вариантов декомпозиции требований:
- Сформировать **не более трёх вариантов**
- Сравнить их по:
  - Атомарности
  - Трассируемости
  - Зависимости задач
  - Риску дублирования
  - Удобству реализации
- Выбрать наиболее обоснованный вариант

### 🔁 Self-Refine / Critic
После формирования Jira Tasks Artifact проверь его по **Completion Criteria**. Исправь:
- Дубли
- Чрезмерно крупные задачи
- Потерю требований
- Необоснованные Acceptance Criteria

## 📤 Выходные данные (Output)

Создай **Jira Tasks Artifact**. Для каждой задачи укажи:

| Поле | Описание |
|---|---|
| **Local ID** | Временный идентификатор |
| **Summary** | Понятное название задачи |
| **Description** | Описание на основании Requirement Review |
| **Source Requirements** | Ссылки на исходные требования |
| **Acceptance Criteria** | Критерии приёмки из подтверждённых требований |
| **Dependencies** | Зависимости от других задач (если применимо) |
| **Priority** | Приоритет или признак, что Priority требует внешнего решения |
| **Open Questions / Blockers** | Вопросы или блокирующие факторы, влияющие на создание задачи |

> ⚠️ **Важно:** Jira Issue Key **не должен присутствовать** как фактически созданный, пока агент не выполнит Jira Tool и не получит подтверждение.

## 📜 Контракт артефакта (Artifact Contract)

| Поле | Значение |
|---|---|
| **Producer** | Skill `task-design` |
| **Consumer** | Agent, этап создания задач через Jira Tool |
| **Artifact** | Jira Tasks |
| **Validation** | Completion Criteria этого Skill |

### 🚨 Error Handling
Если Requirement Review содержит критическую неоднозначность, не позволяющую надёжно сформировать конкретную задачу — пометь соответствующую часть как **BLOCKED/REQUIRES_HUMAN_DECISION** вместо самостоятельного выбора.

## ✅ Критерии завершения (Completion Criteria)

- [ ] Каждая задача имеет основание в Requirement Review
- [ ] Каждое значимое подтверждённое требование либо покрыто задачей, либо явно отмечено как не требующее отдельной задачи
- [ ] Summary и Description понятны без повторного чтения всей истории агента
- [ ] Acceptance Criteria не содержат придуманных бизнес-правил
- [ ] Traceability к требованиям сохранена
- [ ] Необоснованные дубликаты отсутствуют
- [ ] Критические Ambiguities и Conflicts не скрыты
- [ ] Artifact готов к передаче агенту для создания задач через Jira Tool
