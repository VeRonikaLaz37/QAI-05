## 1. Scope

Конфигуратор сэндвич-панелей — UI-компонент для формирования заказа с расчётом стоимости на основе площади (руб./м²). В scope входят:

- **Frontend:** Интерфейс конфигуратора (список позиций, блок итогов, валидация на клиенте)
- **Backend:** 4 API-эндпоинта (настройки, добавление в корзину, удаление, получение корзины)
- **Бизнес-логика:** Формулы расчёта площади/стоимости, валидация раскроя (размещение на листе с учётом поворота)

**Вне scope:**
- Процесс оформления/оплаты заказа
- Авторизация/аутентификация пользователя
- Управление каталогом продуктов и категорий
- Сохранение/восстановление состояния корзины между сессиями
- Мультипозиционный раскрой (несколько изделий на одном листе)

### 2.2 Описание ключевых требований

**FR-18 — Валидация раскроя:**  
Формула: `(W ≤ Sheet_W AND L ≤ Sheet_L) OR (W ≤ Sheet_L AND L ≤ Sheet_W)`  
Это означает, что панель может быть размещена на листе в двух ориентациях: прямой или повёрнутой на 90°. Достаточно выполнения хотя бы одного из условий.

## 9. Conflicts

| ID | Противоречие | Описание | Критичность |
|----|-------------|----------|-------------|
| **CON-01** | Отсутствует кнопка «Добавить в корзину» в описании UI | Сценарий 6.6 упоминает «кнопка добавления в корзину неактивна», но в структуре строки (2.1.1) такая кнопка не описана. В API (3.2) есть POST /api/cart/add, но из UI-описания неясно, как пользователь инициирует добавление | **Высокая** |
| **CON-02** | Формула расчёта vs API-ответ | В API ответе `area_m2: 1.44` и `price_rub: 2880` для 4 панелей 1200×1200 при 500 руб./м². Проверка: S = 1.44 м², Price = 1.44 × 500 × 4 = 2880. Формула из раздела 5: Price = S × cost_one_rub × quantity. Это совпадает. Однако в UI (2.1.1) указано «Итого: (S × Стоимость м² × Кол-во) руб.» — та же формула. Конфликта нет, но есть риск путаницы: area_m2 в ответе — это площадь **одной** панели или **итого**? | Средняя |
| **CON-03** | Наличие API удаления, но отсутствие UI-описания для удаления из корзины | API `DELETE /api/cart/items/{item_id}` существует, но в UI описана только кнопка DEL для удаления строки **из списка конфигуратора** (до добавления в корзину). Как удалять из корзины? | Средняя |

## Summary

### Общая оценка требований

| Параметр | Оценка |
|----------|--------|
| **Полнота** | Средняя — основное поведение описано, но есть пробелы (кнопка добавления в корзину, округление, error handling) |
| **Чёткость** | Средняя — есть неоднозначности (округление, тип quantity, поведение при пустом списке) |
| **Тестируемость** | Высокая для основных сценариев, низкая для edge cases и error scenarios |
| **Покрытие негативных сценариев** | Среднее — базовые ошибки валидации описаны, но error handling API не раскрыт |
| **Готовность к тест-дизайну** | Требуется уточнение по OQ-01, OQ-02, OQ-04 перед проектированием тест-кейсов |

### Ключевые находки

1. **Критично:** Отсутствует описание кнопки «Добавить в корзину» (CON-01, OQ-01) — невозможно спроектировать полный позитивный сценарий.
2. **Критично:** Правила округления не определены (AMB-01, OQ-02) — расчёты могут расходиться между фронтом и бэком.
3. **Среднее:** Ограничения для поля «Количество» не заданы (min > 0 указано, max не определён).
4. **Среднее:** Error handling API не описан — невозможно спроектировать негативные API-тесты.
