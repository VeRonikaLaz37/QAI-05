## 1. Scope

Конфигуратор раскроя сэндвич-панелей с расчетом стоимости за м² на странице товара/категории:

- выбор продукта из списка (продукт имеет размеры `length` и `width`);
- ввод пользователем ширины, длины, количества и маркировки;
- автоматический расчет площади и стоимости;
- добавление в корзину с сохранением введенных параметров;
- валидация размеров на фронте и бэке (помещение изделия на лист с учетом поворота);
- получение настроек конфигуратора (минимальные значения) при переходе в категорию.

Источник: Confluence 622593, § Задача, пп. 1–7.

## 2. Requirements

| ID | Requirement |
|---|---|
| FR-1 | Пользователь может выбрать продукт из списка. Продукт имеет размеры `length` и `width`. |
| FR-2 | Пользователь указывает ширину, длину, количество и маркировку. |
| FR-3 | Площадь рассчитывается автоматически: `площадь = ширина × длина`. |
| FR-4 | На основании площади отображается стоимость: `стоимость = площадь × cost_one_rub`. |
| FR-5 | При добавлении в корзину сохраняются введенные параметры. Пример тела запроса: `{ "configurator": "sandwich_m2", "product_id": 52098, "product_category_id": 13551, "quantity": 4, "width": 1200, "length": 1200 }`. |
| FR-6 | Валидация выполняется и на фронте, и на бэке. Проверяются введенные размеры: указанное изделие должно поместиться на лист с учетом возможности поворота изделия при раскрое. |
| FR-7 | При переходе в категорию получаются настройки конфигуратора с допустимыми минимальными значениями: `min_length: 100`, `min_width: 100`. |

## 3. Business Rules

| ID | Rule | Source |
|---|---|---|
| BR-1 | `площадь = ширина × длина` | FR-3 |
| BR-2 | `стоимость = площадь × cost_one_rub` | FR-4 |
| BR-3 | Изделие должно помещаться на лист при раскрое, допускается поворот изделия (90°) | FR-6 |
| BR-4 | Минимально допустимые размеры: `min_length = 100`, `min_width = 100` | FR-7 |
| BR-5 | Добавление в корзину выполняется запросом с `configurator = "sandwich_m2"` и параметрами продукта/категории/количества/размеров | FR-5 |

## 4. Acceptance Criteria

Явные Acceptance Criteria в источнике отдельным блоком не выделены (см. RK-6 / OQ-9). Косвенно следуют:

- AC-1 (из FR-3): площадь корректно высчитывается из введенных ширины и длины.
- AC-2 (из FR-4): стоимость отображается как площадь × `cost_one_rub`.
- AC-3 (из FR-5): после добавления в корзину введенные параметры сохранены.
- AC-4 (из FR-6): валидация размеров отклоняет изделие, не помещающееся на лист (с учетом поворота), и на фронте, и на бэке.
- AC-5 (из FR-7): при переходе в категорию загружены настройки с `min_length=100`, `min_width=100`.

## 5. Validation Rules

| ID | Rule |
|---|---|
| VR-1 | `width >= min_width (100)` |
| VR-2 | `length >= min_length (100)` |
| VR-3 | Изделие помещается на лист с учетом поворота: `(w <= sheet_W AND l <= sheet_L) OR (w <= sheet_L AND l <= sheet_W)` (BR-3; параметры листа в источнике не заданы — MIS-4). |
| VR-4 | Валидация выполняется на двух уровнях: frontend и backend (FR-6). |

Значимые граничные условия, следующие из требований:

- `width = 100`, `length = 100` (точно на минимуме);
- `width = 99`, `length = 99` (на 1 ниже минимума);
- размеры, ровно помещающиеся на лист (в обе ориентации);
- размеры, помещающиеся только с поворотом;
- размеры, не помещающиеся ни с поворотом, ни без.

## 6. Dependencies

- DEP-1: список продуктов и их размеры (`length`, `width`) — источник данных продукта (FR-1).
- DEP-2: параметр `cost_one_rub` — источник цены за м² (FR-4).
- DEP-3: API настроек конфигуратора (min_length, min_width), вызываемый при переходе в категорию (FR-7).
- DEP-4: API добавления в корзину (FR-5), параметры `product_id`, `product_category_id`.
- DEP-5: параметры листа раскроя — необходимы для проверки помещения (FR-6).

## 10. Positive Flows

- PF-1: Переход в категорию → получены настройки конфигуратора (min_length=100, min_width=100).
- PF-2: Выбор продукта из списка → отображение атрибутов length/width.
- PF-3: Ввод ширины/длины/количества → автоматический расчет площади (`w × l`).
- PF-4: Отображение стоимости (`площадь × cost_one_rub`).
- PF-5: Добавление в корзину → параметры сохранены.
- PF-6: Валидация: корректные размеры (≥ min, помещаются на лист) → фронт и бэк принимают → добавление успешно.
- PF-7: Изделие помещается на лист **только с поворотом** → принимается (BR-3).
- PF-8: Несколько позиций с разными размерами в одной корзине (quantity = N, параметры каждой позиции сохраняются).

## 11. Negative Flows

- NF-1: `width < 100` или `length < 100` → отклонение (фронт и бэк).
- NF-2: Изделие не помещается на лист ни в одной ориентации → отклонение (фронт и бэк).
- NF-3: Нечисловые/негативные значения размеров или количества → отклонение валидацией.
- NF-4: Фронт-валидация обойдена (прямой API-вызов) → бэк-валидация отклоняет (FR-6).
- NF-5: Некорректные/отсутствующие `product_id` / `product_category_id` в запросе корзины → отклонение бэком (контракт FR-5; коды ошибок MIS-7).

## 12. Boundaries

- B-1: `min_length = 100`, `min_width = 100` (точное равенство — допустимо; на 1 меньше — нет).
- B-2: Изделие ровно по размеру листа (в обе ориентации) — допустимо.
- B-3: Изделие, помещающееся только с поворотом — допустимо.
- B-4: Размер на 1 ед. больше габаритов листа — недопустимо.
- B-5: Верхняя граница размеров не определена (MIS-8), кроме проверки на лист.
- B-6: Площадь/стоимость при больших размерах — потенциальные переполнения/формат не задан (AMB-7).
