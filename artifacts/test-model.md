### TC-11: Валидация — поворот изделия при раскрое (risk-based)

| Поле | Значение |
|---|---|
| **Local ID** | TC-11 |
| **Qase ID** | QT-11 |
| **Title** | Валидация: поворот изделия при раскрое (risk-based) |
| **Source Requirement** | VR-02 |
| **Risk Reference** | R-01 — неполная спецификация валидации на листе |
| **Priority** | High |
| **Type** | Functional |
| **Behavior** | Positive |

**Preconditions:** Настройки конфигуратора загружены, размеры листа известны

**Steps:**
1. Ввести размеры изделия, при которых оно не помещается без поворота, но помещается с поворотом на 90° → Валидация проходит
2. Проверить, что поворот учитывается корректно → Изделие размещается на листе с учетом поворота

### TC-12: Расхождение валидации между фронтом и бэком (risk-based)

| Поле | Значение |
|---|---|
| **Local ID** | TC-12 |
| **Qase ID** | QT-12 |
| **Title** | Расхождение валидации между фронтом и бэком (risk-based) |
| **Source Requirement** | VR-03 |
| **Risk Reference** | R-03 — расхождение фронтовой и серверной валидации |
| **Priority** | High |
| **Type** | Integration |
| **Behavior** | Positive |

**Preconditions:** Пользователь заполнил форму раскроя

**Steps:**
1. Ввести корректные данные, проходящие фронтовую валидацию → Данные отправлены на сервер
2. Проверить, что бэкенд валидация также проходит → Ответ сервера: успех
3. Ввести данные, проходящие фронтовую валидацию, но не проходящие бэкенд (если возможно) → Бэкенд возвращает ошибку, идентичную фронтовой
